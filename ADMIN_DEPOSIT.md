# /addep — депозит от администратора

В личном чате с ботом администратор из `ADMIN_ID` в `conf.json` может выполнить:

```text
/addep @durov 50
```

Сумма — целое число **от 1 до 1 000 000 Stars**. Username регистронезависим. Получатель должен быть известен боту: команда ищет сохранённый Telegram username, а не создаёт аккаунт по произвольному имени. Telegram Bot API не используется для произвольного поиска частных пользователей. Если username не найден или связан с несколькими записями, начисление не выполняется. При смене username пользователь должен снова открыть бота, чтобы обновить сохранённые данные.

## Что происходит

Одна SQLite-транзакция:

1. Проверяет администратора и идентификатор исходного сообщения.
2. Находит конкретный Telegram user ID по сохранённому username.
3. Увеличивает доступный баланс на указанную сумму.
4. Регистрирует депозит в `payments` и событие в `webapp_wallet_events`.
5. Выполняет штатное реферальное начисление с обычной ставкой; уведомление рефереру идёт через существующую очередь.
6. Сохраняет аудит в `webapp_admin_deposits`: администратор, чат, сообщение, получатель, username, сумма, баланс после начисления и дата.

Сумма учитывается как полноценный депозит для истории, статистики, требований к депозитам при активации чеков и минимального депозита для вывода. При этом **отыгрыш чеков и другие ограничения вывода не обходятся**. Никаких запросов на создание платёжного счёта, покупки Stars или переводов через провайдеров эта команда не делает: администратор сам выдаёт внутренний депозит.

В истории отображается **«Депозит от администратора»**, а не якобы оплаченный счёт CryptoBot/xRocket/Telegram. Источник отличается префиксом `admin-deposit:`. Это не подтверждение получения внешних денег; ответственность за такие начисления остаётся у администратора.

## Защита от повторов

Повторная доставка **того же сообщения** (одинаковые Telegram chat ID/message ID) не увеличивает ни баланс, ни депозит, ни реферальное вознаграждение повторно. Даже если сообщение с подтверждением не отправилось после записи в БД, повторная доставка вернёт прежний результат. Изменённые параметры уже использованного сообщения отклоняются.

**Новая отправленная команда — новое начисление.** Не отправляйте её снова, если лишь не получили подтверждение: сначала проверьте историю/аудит. Команда не пытается угадывать, является ли новая команда намеренной повторной выдачей.

Группы/супергруппы и неавторизованные отправители не могут начислить депозит. Ошибка записи/реферального учёта откатывает всю финансовую транзакцию.

Реализация находится только в `server.py`; дополнительные Python-модули для хостинга не нужны. Автотесты: `tests/test_admin_deposit.py`. Проверки выполняются с временными базами и без реальных денежных операций.
