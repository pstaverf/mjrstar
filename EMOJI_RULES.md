# Одиночные Telegram-игры

Броски выполняются существующим Telegram-ботом в существующем игровом канале через `send_dice`. Значения не генерируются WebApp и не принимаются от клиента. Для каждого броска сохраняется отдельная ссылка Telegram. При нескольких бросках ставка списывается один раз, до первого броска; ошибка не запускает переброс, а возвращает полную ставку.

## Математика

Для расчёта используются равновероятные значения 1–6 для костей/боулинга/дартса, 1–5 для футбола/баскетбола и 1–64 для слотов, как предполагают таблицы исходного интерфейса. Это модель расчёта коэффициентов, не гарантия распределения стороннего сервиса Telegram.

Для обычного исхода с N возможными последовательностями и W выигрышными последовательностями коэффициент в сотых равен floor(90 × N / W). Если дуэль возвращает ставку при D равенствах, коэффициент победы равен floor((90 × N − 100 × D) / W). Равенство возвращает ставку полностью. Перебор исходов рассчитывает вероятность именно выбранного условия, а не доверяет коэффициенту из запроса.

Выплата в копейках равна floor(ставка_в_копейках × коэффициент_в_сотых / 100). Поэтому итоговый теоретический возврат не превышает 90%; округления могут немного уменьшать его. RTP не означает шанс выиграть конкретную ставку.

Лесенки сохраняют форму клиентских таблиц, но нормируются на средний возврат не выше 90%. Для исходного значения Tᵢ в сотых новое значение равно floor(Tᵢ × 90 × N / ΣTᵢ). Копилка слотов нормирует суммы трёх символов; таблица каждого символа округляется отдельно, затем суммируется. Лаки 7 нормирует таблицу по распределению числа семёрок на шести барабанах.

Серверные коэффициенты возвращаются `/api/{game}/multipliers` и `/api/{game}/quote?outcome=...`. Выбранный коэффициент в интерфейсе уточняется по quote, а перед отправкой ставки клиент повторно ожидает этот ответ. Изменение коэффициента, выплаты, баланса или результата в JSON клиента не влияет на расчёт.

## Правила составных исходов

- Кости: меньше — 1–3, больше — 4–6. «67» — сумма трёх кубов 6 или 7. Комбинация сравнивает набор с учётом повторений, но без порядка. Точный исход проверяет каждый куб отдельно; пустой список разрешает любое значение этого куба. Стрит использует тройки 123/234/345/456 и выбранное направление. Дубль/трипл требуют одинаковых значений из выбранного списка. Рост/спад строго монотонны, без равных значений.
- Сектор кубов: первый — 1–2, второй — 3–4, третий — 5–6.
- Боулинг: значения Telegram 1–6 соответствуют 0/1/3/4/5/6 сбитым кеглям. Диапазоны суммы используют число сбитых кеглей, не сырые значения Telegram.
- Дартс: 1 — промах, 2/3/4/5 — секторы 4/3/2/1, 6 — центр. Белые — 3/5, красные с центром — 2/4/6; «2 Красных сектора» исключает центр. «Две рядом» — соседние значения по близости к центру; «Светофор» — один белый и один красный результат с допустимым центром. Дуэль и сравнение близости используют порядок значений Telegram.
- Баскетбол: гол — 4/5, промах — 1/2/3. Прокрут — 2/4, чистый гол — 5. «Только третий» — первые два промаха, затем гол.
- Футбол: гол — 3/4/5, промах — 1/2. Штанга — 2/4, удар об штангу — только 2. «Камбэк» — промах, гол, гол. Дуэль точности возвращает ставку при равенстве; дуэль штанги выигрывает, если выбранный участник попал в штангу, а другой — нет.
- Дубль в трёх бросках — ровно одна пара; трипл — три одинаковых. «Все разные» исключает любые повторения. «Без» исключает соответствующий результат во всех бросках. «1+»/«2+» означают как минимум указанное число подходящих бросков.
- Слоты: последовательные разряды числа Telegram минус один в основании 4 соответствуют символам Бар/Виноград/Лимон/Семёрка. «Комбо» — тройка одинаковых символов в одном вращении. «Уникальные символы» проверяет различие трёх символов в каждом вращении отдельно. «Любые N+» проверяет число одинаковых символов на всех барабанах серии. Дуэль символа сравнивает его количество в двух вращениях, выбранный знак равенства — отдельная выигрышная ставка, а не возврат.

## Сохранение и ошибки

`webapp_emoji_jobs` хранит идентификатор восстановления и стадию запроса; `webapp_requests` защищает повторы; `webapp_rounds` содержит только завершённые игры. Общие списание, выплата, история и финальный ответ фиксируются транзакциями SQLite с общим балансом бота. Ожидание Telegram не удерживает блокировку базы. У игрока может быть только одна незавершённая одиночная Telegram-игра одновременно.

После перезапуска незавершённые задания получают полный возврат без повторного броска. Сбой записи выплаты откатывает выплату и историю; отдельная транзакция возвращает исходную ставку. `/api/play/result?rid=...` возвращает состояние только владельцу задания.
