# Все секреты и настройки запуска — conf.json

Рабочий файл **`conf.json` расположен рядом с `server.py`**. Менять Python-код для настройки токенов и кошелька больше не нужно. Формат — один JSON-объект с именами из `conf.example.json`. Не добавляйте комментарии или запятые после последнего поля.

В текущем рабочем окружении существующие настройки перенесены в приватный `conf.json` без печати значений. Реальная seed-фраза и новый Fragment JWT не были добавлены. **Рабочий `conf.json` исключён из Git**, поэтому после скачивания проекта из GitHub на новый хостинг его нужно создать/перенести отдельно. В репозитории находится только безопасный шаблон `conf.example.json` с пустыми секретами.

## Создание на новом сервере

Если `conf.json` уже есть, не перезаписывайте его шаблоном. Иначе скопируйте `conf.example.json` под именем `conf.json`. Назначьте владельцем пользователя приложения и права **0600** (например, `chmod 600 conf.json`). Файл не должен быть символической ссылкой. Открывайте его в редакторе на сервере; не вводите секреты в команды shell и не отправляйте их в чат.

Файл ищется рядом с **самим `server.py`**, а не в произвольной текущей папке. Изменения применяются после перезапуска. Частичный JSON допустим: пропущенные поля получают безопасные значения из шаблона; секреты не подставляются из старого Python-кода или переменных окружения.

## Бот и WebApp

| Поле | Что указать |
|---|---|
| `BOT_TOKEN` | Токен своего Telegram-бота из BotFather. |
| `BOT_USERNAME` | Username бота без `@`. |
| `ADMIN_ID` | Положительный числовой Telegram ID администратора, не username. |
| `WEBHOOK_HOST` | Публичный HTTPS-адрес приложения, например `https://your-domain.example`. |
| `WEBHOOK_PATH` | Путь webhook, обычно `/webhook`. |
| `WEBHOOK_SECRET` | Своя случайная секретная строка из 1–256 символов `A-Z a-z 0-9 _ -`. Не токен бота. |
| `WEBAPP_HOST` | Интерфейс прослушивания, обычно `0.0.0.0`. |
| `WEBAPP_PORT` | Числовой порт, в шаблоне `16341`. |
| `CHANNEL_ID` | Username канала вида `@channel` или числовой Telegram ID канала. |
| `CHANNEL_URL` | Ссылка на свой канал. |
| `CHAT_URL` | Ссылка на свой чат. |

`BOT_TOKEN`, `ADMIN_ID`, `WEBHOOK_HOST`, `WEBHOOK_SECRET` нужны для обычного запуска. Сервер проверяет их до создания Telegram-клиента. Без файла/обязательных полей боевой запуск заблокирован, а импорт и офлайн-проверка кода доступны. `DB_PATH` не перенесён и не изменён: существующая база `bot.db` используется как прежде.

## Пополнение CryptoBot / xRocket

| Поле | Что указать |
|---|---|
| `CRYPTOBOT_API_TOKEN` | Токен Crypto Pay API. |
| `XROCKET_API_TOKEN` | Токен/JWT своего xRocket API. |
| `XROCKET_WEBHOOK_SECRET` | Секрет для проверки webhook xRocket из настройки интеграции. |

Пустые ключи не включают соответствующий способ оплаты. Настройка JSON не проверяет ключи живым запросом и не создаёт счета.

## Вывод Telegram Stars

| Поле | Что указать |
|---|---|
| `FRAGMENT_API_JWT` | **Fragment Connection JWT** из личного кабинета провайдера; не токен бота. |
| `FRAGMENT_CURRENCY` | `ton` либо `usdt_ton`. Для USDT-оплаты провайдеру всё равно нужен TON на gas. |

Если JWT пустой, вывод не включается. Для уже созданных заказов нужен исходный JWT; его смена не должна использоваться для повторной покупки после таймаута.

## Серверный TON-кошелёк

| Поле | Что указать |
|---|---|
| `TON_WALLET_MNEMONIC` | Строка из 24 слов native TON-мнемоники через пробел. **Только на сервере**, никогда в Git. |
| `TON_WALLET_SEED_FILE` | Альтернатива inline-фразе: путь к приватному seed-файлу `0600`. Относительный путь считается от папки `conf.json`. |
| `TON_WALLET_VERSION` | `v4r2` или `v3r2`. V5 пока не поддерживается; нельзя подставлять вместо него V4. |
| `TON_WALLET_WORKCHAIN` | Число `0`. |
| `TON_WALLET_ID` | `null` для стандартного subwallet ID либо реальный uint32 wallet ID. |
| `TONKEEPER_ADDRESS` | Необязательный ожидаемый адрес. При заполнении должен совпасть с полученным из seed/версии/wallet ID. |
| `TON_RPC_URL` | URL своего **mainnet v3-совместимого индексатора**. Seed не заменяет узел. Не обычный lite-server/JSON-RPC. |
| `TON_USD_RATE` | Строка с актуальным числом USD за один TON, например `"2.50"`. Это ручной курс, не биржевой поток. |

Заполняйте **только одно** из `TON_WALLET_MNEMONIC` и `TON_WALLET_SEED_FILE`. Для остальных полей неиспользуемого TON-кошелька можно оставить значения шаблона. Ошибка seed/адреса или недоступная сеть не подтверждает поступление денег и не приводит к зачислению.

`conf.json` — приватный файл на сервере, но не зашифрованное хранилище/HSM. Пользователь процесса приложения и администратор сервера могут читать его. Используйте отдельный hot wallet с небольшим остатком, защищайте резервные копии, не размещайте файл в папке публичных ресурсов. Старые секреты из прежних коммитов автоматически не исчезают из Git-истории; при необходимости их нужно сменить у провайдеров.

## Проверки

```sh
python server.py --check-config
python server.py --check
python server.py --check-ton-wallet --local-only
python server.py --check-ton-wallet
python server.py
```

- `--check-config`: проверка JSON/обязательных полей для запуска бота, **без сетевых запросов** и без вывода значений секретов.
- `--check`: проверка загрузки кода, не проверка живых платёжных ключей.
- `--check-ton-wallet --local-only`: локальная проверка seed/адреса.
- Без `--local-only` проверка кошелька обращается к вашему TON-индексатору.
- Обычный запуск стартует бота и WebApp вместе.

Файл и его копии через ссылки в публичных папках недоступны через штатный обработчик ресурсов. Не настраивайте Nginx/другой веб-сервер на выдачу всего каталога исходников: он должен также запрещать доступ к `conf.json`, его копиям, seed-файлам и базам.
