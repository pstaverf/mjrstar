# Рабочие ставки, WebSocket и тикеты поддержки

## Исправленная блокировка ставок

Клиент читал `accepting` из `GET /api/bets/status`, а сервер возвращал только `accepted` и `betsAccepted`. Это превращало `betsAccepted` в `false` и блокировало кнопки. Ответ теперь содержит `accepting: true`; клиент также понимает прежние булевы поля. Отсутствующее поле больше не выключает ставки само по себе.

Списания и выплаты остаются на сервере, транзакционно, с общим балансом `bot.db`. Фронтенд не может подтвердить себе выплату. Сохраняются проверки суммы, владельца, подписи initData, версии раунда и повторных запросов. Игровые API уже зарегистрированы в `games_backend.py`, `complete_games.py` и подключённых игровых модулях. WebSocket не заменяет эти маршруты.

Одиночные и PvP Telegram-игры требуют настоящего бота с правом отправлять `send_dice` в настроенный `CHANNEL_ID`. Без бота/канала только эти режимы отключаются; результат не заменяется локальной случайной заглушкой. `GET /api/subscription/check` теперь проверяет статус через `get_chat_member`, с таймаутом и явной ошибкой при недоступности Telegram. Этот маршрут обслуживает существующее клиентское окно подписки и не вводит новый денежный бонус.

## DogHouse отключён

Карточка удалена из `app_shell.html`, открытие из старых ссылок блокируется, `/api/games/off` содержит `doghouse`, новые ставки `/api/doghouse/*` получают HTTP 410 с `GAME_REMOVED`. Режим исключён из лимитов и популярных игр. Архивные исходники и записи старых раундов не удалены, чтобы не потерять историю. Архивные математические тесты запускают модуль отдельно, вне production-маршрутов.

## WebSocket

- `POST /api/realtime/session`: обычный подписанный Telegram-запрос. Возвращает одноразовый случайный билет, живущий 30 секунд.
- `GET /api/ws`: WebSocket Upgrade. Первое сообщение в течение пяти секунд: `{"ticket":"..."}`. В URL не передаются ни initData, ни билет.
- До успешной аутентификации сервер не посылает баланс, обращения или игровые данные. Билет погашается один раз. Межсайтовый Origin отклоняется.
- После `ready` сервер присылает `state`: только баланс подключённого пользователя, ревизию доступных ему тикетов и публичные идентификаторы/фазы текущих Crash/Roulette/Portal/Race/Bomb/Sumo. Скрытых исходов, сидов, приватных ставок и чужих балансов в этих снимках нет.
- Состояние сравнивается каждые две секунды, неизменившиеся снимки не отправляются. Канал read-only: новые команды клиента закрывают соединение, а не выполняют ставку.
- Heartbeat 20 секунд; сессия переподключается через 15 минут, с новым подписанным запросом. Лимит — 3 соединения пользователя и 64 соединения процесса.
- Клиент обновляет баланс и тикеты, а при изменении фазы игры запрашивает её актуальное HTTP-состояние. Старый polling сохраняется как резерв, если WebSocket недоступен. Есть backoff переподключения, закрытие при скрытии страницы и защита от параллельного подключения.

Билеты и соединения хранятся в памяти процесса. Текущая схема рассчитана на один backend-процесс. Для нескольких worker нужны sticky routing или общее хранилище билетов/событий. WebSocket не решает проблемы отсутствующих ассетов, неверного токена бота или старого HTML.

## Тикеты

Все записи хранятся в таблицах `webapp_support_*` той же `bot.db`; путь базы не менялся.

Подключены:

- `GET /api/support/state`, `/unread`, `/ticket?id=...&after=...&rev=...`;
- `POST /api/support/ticket/create`, `/ticket/reply`, `/ticket/close`;
- `POST /api/support/message/edit`, `/message/delete`;
- `POST /api/support/upload`, `/file/delete`, `GET /api/support/file?t=...`;
- `POST /api/support/typing`, `/faq/view`.

Пользователь видит только свои тикеты. Администратор определяется серверным `ADMIN_ID`, а не полем `isAdmin` клиента. Зайдите в Mini App из аккаунта с этим ID, откройте «Помощь»: заголовок списка будет «Все обращения · администратор». Там можно открыть чужое обращение, ответить и закрыть его. Пользователь увидит ответ в этой же переписке. Новое сообщение возобновляет закрытый тикет.

Вложения доступны только автору обращения и администратору. Поскольку `<img>` не умеет добавлять заголовок initData, интерфейс получает фото через авторизованный `fetch` и отображает Blob URL. API не делается публичным ради картинок. Лимиты: 4 изображения на сообщение, 2 MB на фото, 40 загрузок пользователя в сутки; до 10 открытых обращений. Неприкреплённые файлы старше суток очищаются при старте и новых загрузках. Прикреплённые остаются в базе вместе с перепиской.

Повторы создания/ответа защищены Idempotency-Key. Редактировать и удалять можно свои сообщения в открытом обращении в течение 48 часов; прежняя версия сохраняется в аудите. Read/unread разделён для пользователя и администратора. Изменения доступны через incremental polling и WebSocket-инвалидацию. Список ограничен 200 последними тикетами, пачка сообщений — 500; расширенная административная пагинация пока не реализована.

Честные ограничения: автоматические Telegram-уведомления о тикетах, автоответы, расписание операторов, управление банами поддержки и отдельная административная панель в эту реализацию не входят. Ответы администратора работают в существующем разделе «Помощь». Не подставляются фальшивые FAQ, операторы или статус «Онлайн».

## Установка

Обновляйте комплект целиком: `main.py`, все подключённые Python-модули (включая новые `support_backend.py`, `realtime_backend.py`), `app.js`, `app_shell.html`, `index.html`, `styles.css`, `support.js`, `support.css`, `sw.js` и ассеты. Не разворачивайте старый `or.zip` поверх обновления. В `requirements.txt` записаны проверенные версии aiohttp, aiogram и aiosqlite. Требуется Python 3.10+; тесты выполнены на Python 3.11.

Новая метка ресурсов: `majorstars-performance-20261107-6`; Service Worker: `mjrstar-static-v30`. Перезапустите существующий сервис после замены Python-модулей. Перед обновлением сделайте согласованный SQLite backup; не удаляйте `bot.db-wal`/`bot.db-shm`.

Прокси должен направлять `/api/*`, `/app`, `/app/` и статику на тот же backend `0.0.0.0:16341`. Для Nginx внутри существующей конфигурации проксирования `/api/ws` нужны:

```nginx
location = /api/ws {
    proxy_pass http://127.0.0.1:16341;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 75s;
    proxy_buffering off;
}
```

Это серверный адрес Nginx, не URL браузера. Клиент использует `wss://<текущий-домен>/api/ws`. Для Cloudflare должны быть разрешены WebSocket. Фактическая конфигурация домена/прокси в этом сеансе не менялась.
